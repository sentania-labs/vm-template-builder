# windows2022-bare

## Purpose
Clean Windows Server 2022 template for lab workloads that don't need
first-boot automation. Deploy-and-login base. Built from the same
provisioner chain and hardware as `windows2025-bare` ([bare.md](bare.md)).

## OS + version
Windows Server 2022, Standard edition, Desktop Experience (non-eval).

- **Media:** Microsoft Server 2022 evaluation ISO
  (`SERVER_EVAL_x64FRE_en-us.iso`), remastered with `efisys_noprompt.bin`
  and staged as content library item `server2022-remastered`
  (`server2022-remastered.iso`).
- **Install:** `autounattend/autounattend-2022.xml` selects
  `/IMAGE/NAME` = `Windows Server 2022 SERVERSTANDARD` (Desktop Experience),
  which installs `ServerStandardEval`. It carries no product key: eval setup
  rejects a Standard GVLK.
- **Edition conversion:** `setup/15-set-edition.ps1` runs
  `DISM /online /Set-Edition:ServerStandard /ProductKey:VDYBN-27WPP-V4HQT-9VMD4-VMK7H /AcceptEula /NoRestart`
  after VMware Tools, Packer reboots, and the same script then asserts
  `DISM /online /Get-CurrentEdition` reports `ServerStandard` before the
  build continues. Skipped if the edition is already `ServerStandard`.
- **Activation key:** Microsoft-published KMS client key (GVLK) for Server
  2022 Standard, `VDYBN-27WPP-V4HQT-9VMD4-VMK7H`. Activates against the lab
  KMS; unactivated without one. Check with `slmgr /dlv`.
- **vSphere guest OS type:** `windows2019srvNext_64Guest`.

## Pre-installed software
- VMware Tools (installed from ESXi host ISO during build)
- All Windows Updates current as of build time (PSWindowsUpdate, two
  passes)
- Sentania Lab Root 2 CA in `Cert:\LocalMachine\Root`

## First-boot behavior
None. Sysprep completes with `unattend-bare.xml` (shared with 2025), which
re-seals the local accounts and skips OOBE. The VM boots to the login
screen.

## Lab assumptions
- Target cluster: `vcf-lab-mgmt-cl01`
- Target content library: `vcf-lab-mgmt-contentlibrary`
- vCenter: `vcf-lab-vcenter-mgmt.int.sentania.net`
- Requires `server2022-remastered` content library item uploaded
- Requires VMware Tools ISO at
  `[] /vmimages/tools-isoimages/windows.iso` on the ESXi host
- Requires a reachable KMS for activation after deployment
